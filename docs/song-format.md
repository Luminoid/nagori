# Song data format

Every song is a folder under `data/songs/<slug>/`:

```
data/songs/<slug>/
  song.json          metadata, sections, chords, per-part settings (generated by an importer, or written by hand)
  tracks/<id>.json   one file per part: the tab, bar by bar
  curation.json      what you add by hand; an importer merges it into song.json (optional)
data/songs.json      the home page index, one row per song with `added` (the day it joined) and the curated `artistSort` (`make index` rebuilds it; importers do too)
songs/<slug>.html    the song's own page, written by `make index` from song.html
private/songs/<slug>/  a second collection with the same layout that git ignores (`private` can be a symlink to a private repository) (`make index` writes private/songs.json for it; no pages, no sitemap entries)
data/site.json       the site's name, default language and home page texts
```

Everything is plain JSON. `scripts/validate-song.py <slug>` (or `make validate`) checks a folder against this document; the test suite validates every song.

## song.json

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | The folder name: lower-case letters, digits, dashes. |
| `title`, `artist` | string | Shown as written; never translated. |
| `album`, `year`, `key` | string, number, string | Optional. `key` like `"C minor"` or `"D"`. |
| `bpm` | number | Quarter notes per minute (used when `tempo` is empty). |
| `tempo` | list | Tempo map: `[{ bar, pos, bpm, unit }]`. `bar` is 0-based, `pos` a fraction of the bar (a change mid-bar takes effect there in tab playback), `bpm` counts `unit` notes (4 quarter, 2 half, 8 eighth). The header shows the first entry as written. |
| `timeSignature` | `[beats, unit]` | The first bar's signature. Later changes live on the measures (`sig`). |
| `timeSignatures` | list | Every signature used, for the header. Optional. |
| `tuning` | string | The label for the header, for example `"Standard (E A D G B E)"`. |
| `capo` | number or null | The song-wide capo when every guitar part shares one; otherwise null and each part carries its own. |
| `bars` | number | Bar count; every track file has this many measures. |
| `source` | object | `{ name, url, label }` plus whatever the importer records. The footer links to `url` and shows `label` when there is one (an edition and its licence), else "<name> tab". |
| `video` | object or null | `{ provider: "youtube", id, title, barTimes }` where `id` is the 11-character YouTube id and `barTimes[i]` is the second at which bar `i` starts in the video (one entry per bar, never decreasing). Null means no video, and the page offers tab playback only. |
| `sections` | list | `[{ name, bar }]`, 0-based bars in increasing order, names unique (the importers number repeats: `Chorus`, `Chorus 2`). Names such as `Intro`, `Verse 1`, `Chorus` are translated on the Chinese interface. |
| `chordTimeline` | list | `[{ bar, pos, chord }]`: the chord sounding from that point, `pos` a fraction of the bar (0 to below 1), sorted by bar and position. Drives the now-playing panel, the chord sheet highlight and the fingering labels. |
| `chordSheet` | object or null | `{ source, sections: [{ name, lines }] }`. A line is `{ type: "line", segments: [{ chord, text }] }` (chords over lyrics) or `{ type: "bars", bars: [{ bar, chords }] }` (a progression grid). Section names match `sections` so the sheet follows the playhead (a name the song does not have fails validation; a null name is allowed). |
| `chordLibrary` | object | Voicings for this song's chords, low string to high: `"x35543"`, or `"8 10 10 8 8 8"` when a fret has two digits, with `fingers` in the same layout (`0` open, `x` muted, `1` to `4`). One voicing or a list; the first is what the chords view draws. See "Chord libraries". |
| `fingeringOverrides` | object | Keyed by a position's note set, `"5:8,2:8,1:8"` as `string:fret` pairs, optionally prefixed by a track id and `|`. Each maps `"string:fret"` to a finger. |
| `defaultTrack` | string | The part opened first. |
| `tracks` | list | The parts, see below. |

### Parts (`tracks[]`)

| Field | Type | Notes |
|-------|------|-------|
| `id` | string | Lower-case letters, digits, dashes; unique in the song. |
| `name`, `role` | string | The picker shows `name` with `role` beneath (`"Lead guitar · Fender Telecaster"`; the words before the dot are translated). |
| `instrument` | string | The source's instrument name. Optional. |
| `kind` | `"guitar"` or `"bass"` | Picks the timbre and the level. |
| `strings` | number | 4 to 8. |
| `tuning` | list | MIDI numbers, highest string first: standard guitar is `[64, 59, 55, 50, 45, 40]`, bass `[43, 38, 33, 28]`. |
| `capo` | number | The part's capo. Frets in the tab stay capo-relative; playback adds it. |
| `sound` | string | The guitar sound this part plays with when the listener leaves the picker on "as set per part": `acoustic` (default), `electric`, `overdrive`, `nylon`, `muted`. Ignored for bass. |
| `level` | number | Starting volume, 0 to 1 (default 1). The mixer chip mutes and restores to it. |
| `fingering` | object | `{ maxSpan }`: how many frets the hand spans in one position, 2 to 6 (default 3, meaning four frets). |
| `chordLibrary` | object | Voicings only this part uses (a different tuning, a capo, a signature shape). Same format as the song's. |
| `file` | string | The track file, `tracks/<id>.json`. |

## Track files

```json
{ "id": "lead", "strings": 6, "tuning": [64, 59, 55, 50, 45, 40], "measures": [ ... ] }
```

A measure is `{ "beats": [...], "sig": [4, 4], "marker": "Verse" }`. `sig` appears on the first measure and wherever the time signature changes; `marker` names a section (importers turn markers into `sections`).

A beat:

```json
{ "d": [3, 8], "t": 4, "dots": 1, "tuplet": 3, "ts": true, "te": true,
  "rest": true, "ring": true, "chord": "Cm", "bs": true, "be": true, "stroke": "down",
  "notes": [{ "s": 5, "f": 8, "tie": true, "dead": true, "ghost": true,
              "hp": true, "slide": "up", "bend": 0.5 }] }
```

| Field | Meaning |
|-------|---------|
| `d` | The beat's real length as a fraction of a whole note, dots and tuplets included: a dotted quarter is `[3, 8]`, an eighth triplet `[1, 12]`. |
| `t` | The note value drawn: 1, 2, 4, 8, 16, 32 or 64. |
| `dots`, `tuplet`, `ts`, `te` | Dots; the tuplet's count; tuplet bracket start and end. |
| `rest` | A rest (`notes` is empty). |
| `ring` | Let ring: notes sound until the string is played again. Arpeggiated chords need this to be fingered as one shape. |
| `chord` | A chord label at this beat (fills the chord timeline). |
| `bs`, `be` | Beam start and end. |
| `stroke` | `"down"` or `"up"`: strum direction; the strings are staggered accordingly. |
| `notes[].s` | String index, 0 for the highest string (high e; G on a bass). |
| `notes[].f` | Fret, 0 for open, up to 30. |
| `notes[].tie` | The note continues the previous one on that string instead of sounding again. |
| `notes[].dead` | Muted (x); `ghost`: parenthesized, played softly. |
| `notes[].hp` | The next note on this string is hammered on or pulled off (drawn as an arc, played softer). |
| `notes[].slide` | `"legato"` or `"shift"`: slide to the next note on the string (drawn to it, played as a pitch glide); `"up"` / `"down"`: slide out of the note, rising or falling; `"above"` / `"below"`: slide into the note from above or below. |
| `notes[].bend` | In whole tones: 0.5 is a half step, 1 a whole step. |

Every part of a song has the same number of measures. A bar may be shorter than the signature (a pickup bar) when it is shorter in every part; playback then gives it its written length. A part whose bar is shorter than the others' is padded with a rest instead, never longer.

## Chord libraries

Three libraries stack for every part, first match wins:

1. the part's `chordLibrary`
2. the song's `chordLibrary`
3. the built-in library (`js/chord-library.js`): open chords and the E-form and A-form barre shapes for every root, for six-string standard tuning only

So a song in standard tuning needs no library of its own to get chord diagrams and library-quality fingerings. Write voicings when the recording uses a particular shape (the chords view draws your first voicing), when the tuning is not standard, or when a chord is not in the built-in set. `make propose SONG=<slug> TRACK=<id>` drafts voicings from the shapes a part actually plays. Chord names are matched after normalizing flats and sharps (`B♭6` and `Bb6` are the same chord).

## curation.json

Importers merge this file into `song.json`. Keys every importer understands:

- `album`, `year`, `key`, `duration`, `tuning` (label), `capo`, `defaultTrack`
- `sortArtist`: how the home page's artist sort files the song, e.g. `Bach, Johann Sebastian` for an artist shown as `Johann Sebastian Bach`; defaults to the artist as written (a leading "The" is ignored). Goes into the index row as `artistSort`.
- `added`: the day the song joined the collection, `YYYY-MM-DD`, for the home page's "Newest" order. `make index` records the day a folder first appears and keeps it on rebuilds, so this key is only for backdating.
- `duration` is optional: without it, `make index` takes the length the tempo map gives.
- `tempo` (a tempo map that overrides the source's) and `bpm`
- `sections`: `[{ name, bar }]` when the source has no markers
- `video`: `{ id, title, barTimes }`, or `{ id, title, offset }` to compute bar times from the tempo map, `offset` being the second in the video where bar 1 starts. (The author's Songsterr importer takes the sync points from the source instead when it has them.)
- `chordVocabulary`: chord names detection may use when the source has no chord labels or sheet
- `harmonyTracks`: the part ids detection listens to (default all); `chordTimelinePriority`: which parts' labels win
- `tracks`: per source part, an object with `id`, `name`, `role`, `capo` and the per-part settings above (`sound`, `level`, `fingering`, `chordLibrary`). The MusicXML importer keys this by the part's id in the file (`P1`, `P2`, ...), its name, or its number (`"1"`), and also takes `strings` and `tuning` (a plain notation part becomes a guitar or bass), `transpose` (semitones added to written pitches, `-12` for a guitar part written an octave up) and `vocal: true` (keep a part as the lyric line); the Songsterr importer keys it by part number.
- `chordLibrary`, `fingeringOverrides`

The MusicXML importer also reads `sourceName`, `sourceUrl` and `sourceLabel` (the credit line the song page's footer shows). Importer-specific keys are listed in the README under "Adding a song".

## Adding a song by hand

Write `song.json` and the track files directly; `examples/twelve-bar-blues/` is a complete song in this form (two parts, chord labels, a progression sheet, per-part `sound` and `level`), and `make example` copies it into the collection. Then `make validate SONG=<slug>`, `make index`, and open `song.html?id=<slug>`. `make report SONG=<slug>` prints the fingerings the site will show. A `duration` string on `song.json` (`"3:21"`) shows on the home page.

## site.json

```json
{ "name": "Nagori", "defaultLang": "auto", "url": "https://guitar.luminoid.dev", "copyright": "© 2026 Luminoid · MIT",
  "title": { "en": "", "zh": "" }, "intro": { "en": "", "zh": "" },
  "collection": { "en": "", "zh": "" }, "footer": { "en": "", "zh": "" } }
```

`name` is the brand in the header and the page titles. `url` is where the site is published (`https://tabs.example.com`, or with a sub-path); once it is set, `make index` also writes `sitemap.xml` and `robots.txt` for it. `defaultLang` is `auto` (follow the browser), `en` or `zh`; a visitor's own choice, made with the header toggle or `?lang=`, always wins. The texts are per language and optional: `title` and `intro` replace the home page's heading and paragraph, `collection` puts a visible heading over the song grid, `footer` replaces the footer line on the home and tools pages. `copyright` (one string for every language, `"© 2026 Name · MIT"`) is appended to every footer, the song page's included; leave it empty for no such line.
